## Context

The cluster runs on a single Ubuntu server with K3s, but it is operated with the same practices I would use in a larger environment: nothing is changed by hand, and every change goes through Git.

## Constraints

- Hardware is a single node — availability decisions are conceptual, not real redundancy.
- The environment has to stay understandable after weeks without changes.
- No real secret can ever end up versioned in the repository, not even by accident.

## Architecture

A root ArgoCD Application self-manages and syncs a set of child Applications, one per domain: platform (namespaces, RBAC, Infisical), networking (Traefik, cert-manager, internal DNS), observability, and automation. Sync-waves guarantee that namespaces and Infisical come up before anything that depends on them. Secrets live in Infisical and reach the cluster through an operator that materializes them as native Secrets, per namespace.

## What did not work

The first version let ArgoCD recurse the entire infrastructure folder as a single tree. It worked, but any dependency reading turned into one flat list — there was no way to tell what needed to come up before what. The fix was splitting by domain and using explicit sync-waves.

## Main lesson

GitOps is not just "apply YAML automatically." It is making sure order, domain boundaries, and secrets are part of the design — not a detail resolved during an incident.
