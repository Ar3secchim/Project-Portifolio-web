## Context

The project began as an attempt to reduce the time spent reconciling categories and rebuilding the same analysis every month. The conversational interface came after the data model, not before it.

## Constraints

- Every answer must be explainable from transactions and aggregations.
- The agent cannot execute operations outside its authorized tool set.
- Real data cannot appear in logs, examples, or public screenshots.

## Architecture

The flow is divided into ingestion, normalization, persistence, query tools, and presentation. The agent layer selects a typed tool; the application validates parameters, runs the query, and returns a structured result to be explained.

## What did not work

Asking the model to interpret raw data directly produced answers that were difficult to verify. The model’s role was reduced: calculations and filters stay in code; the model organizes the explanation.

## Main lesson

A useful agent is not one that can access everything. It operates within **clear and observable boundaries**.
