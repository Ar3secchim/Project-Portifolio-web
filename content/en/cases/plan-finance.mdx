## Context

PlanFinance started as a way to stop rebuilding the same financial questions every month in a spreadsheet. It grew into a system with its own backend, a relational database, and an AI agent that answers natural-language questions over WhatsApp — without hiding where each number comes from.

## Constraints

- The agent cannot invent values: every numeric answer must come from a real database query.
- The domain layer (categorization rules, budget calculations) cannot depend on Prisma, Express, or the Claude SDK — only infrastructure knows about those tools.
- Statement-parsing failures (PDF, OFX) must stay visible, never silently swallowed.

## Architecture

The backend follows domain, application, infrastructure, and presentation layers. Use cases orchestrate typed tools the agent can call; each tool fetches data through Prisma and returns a structured result, never free text. An architecture-conformance script runs in CI and fails the build if the domain imports anything from outside it.

## What did not work

The first version let the model interpret raw ledger entries directly to answer questions — it worked until a question got slightly more specific, and the model started "completing" numbers that did not exist. The fix was moving every calculation into code and reducing the model’s role to explaining an already-correct result.

## Main lesson

An AI agent becomes trustworthy with **less** freedom, not more. Defining exactly which tools it can call — and nothing beyond that — is what made the answers verifiable.
