## Contexto

O PlanFinance começou como um jeito de parar de reconstruir as mesmas perguntas financeiras todo mês numa planilha. Evoluiu para um sistema com backend próprio, banco relacional e um agente de IA que responde perguntas em linguagem natural pelo WhatsApp — sem esconder de onde vem cada número.

## Restrições

- O agente não pode inventar valores: toda resposta numérica precisa vir de uma consulta real ao banco.
- A camada de domínio (regras de categorização, cálculo de orçamento) não pode depender de Prisma, Express ou do SDK da Claude — só a infraestrutura conhece essas ferramentas.
- Falhas de leitura de extrato (PDF, OFX) precisam ficar visíveis, nunca silenciosamente ignoradas.

## Arquitetura

O backend segue camadas de domínio, aplicação, infraestrutura e apresentação. Casos de uso orquestram ferramentas tipadas que o agente pode chamar; cada ferramenta busca dados via Prisma e devolve um resultado estruturado, nunca texto livre. Um script de conformidade arquitetural roda em CI e falha o build se o domínio importar algo de fora dele.

## Detalhes que fazem diferença

- **Faturas de cartão em PDF, um parser por banco.** Nubank, Inter e Santander geram layouts diferentes. Cada banco tem uma _specification_ que reconhece o documento e um parser próprio, ligados por um registry: um banco novo entra como uma classe nova, com seu próprio teste, sem tocar nos outros.
- **O modelo decide o que mostrar; o código desenha.** Os gráficos que o agente manda no WhatsApp são renderizados no servidor, de SVG para PNG com fonte embutida — o modelo nunca é chamado para "gerar uma imagem".
- **Só o frontend sai para a internet.** Um Cloudflare Tunnel abre a conexão de dentro para fora e aponta direto para o serviço do frontend; o backend fica inalcançável por construção, e as chamadas de `/api` passam pelo nginx do frontend dentro do cluster. Sem porta aberta, sem IP doméstico publicado.
- **Testes como parte do desenho.** São 106 arquivos de teste entre backend e frontend; só o loop do agente (multi-turno, com chamadas de ferramenta e memória da conversa) tem 828 linhas de teste.

## Trechos do código

O loop do agente: o modelo escolhe a ferramenta, o código faz a conta, e o resultado volta para o modelo explicar.

<CodeSource path="backend/src/application/use-cases/agent/RunFinancialAgent.ts · simplificado" />

```ts
// O skill define o modelo e a lista de ferramentas permitidas.
const enabledTools = FINANCIAL_AGENT_TOOLS.filter((tool) =>
  skill.tools.includes(tool.name),
);

for (let turn = 0; turn < MAX_TURNS; turn += 1) {
  const response = await this.client.messages.create({
    model: skill.model,
    max_tokens: skill.maxTokens,
    system: composeSystemPrompt(skill, { mesAtual, hoje, contas }),
    tools: enabledTools,
    messages,
  });

  if (response.stop_reason === 'end_turn') {
    return toAgentResponse(response, lastResult);
  }
  if (response.stop_reason !== 'tool_use') break;

  messages.push({ role: 'assistant', content: response.content });
  const toolResults: Anthropic.ToolResultBlockParam[] = [];

  for (const block of response.content) {
    if (block.type !== 'tool_use') continue;
    // A conta acontece aqui, em código tipado, com dados do banco.
    const execution = await this.toolExecutor.execute({
      name: block.name,
      arguments: block.input as Record<string, unknown>,
      userId,
      currentMonth,
      today,
    });
    toolResults.push({
      type: 'tool_result',
      tool_use_id: block.id,
      content: JSON.stringify(execution.payload),
    });
  }

  messages.push({ role: 'user', content: toolResults });
}
```

## O que não funcionou

A primeira versão deixava o modelo interpretar diretamente os lançamentos brutos para responder perguntas — funcionava até a pergunta ficar um pouco mais específica, e então o modelo "completava" números que não existiam. A correção foi mover todo cálculo para o código e reduzir o papel do modelo a explicar um resultado já certo.

## Aprendizado principal

Um agente de IA fica confiável quando tem **menos** liberdade, não mais. Definir exatamente quais ferramentas ele pode chamar — e nada além disso — foi o que tornou as respostas verificáveis.
